# SmartDesk 技术文档

## 1. 项目概述

SmartDesk 是一个桌面端智能工作台应用，基于 Electron + Vue 3 构建，当前已迁移的功能分属两个分类：

- **短视频下载**：粘贴抖音 / TikTok / 快手 / 小红书的分享链接，批量解析并下载视频、图文与实况照片。
- **一键裁切头像**：调用内置 Python 子项目 `headcut`，基于 YuNet 人脸检测批量裁切正方形头像，可选 rembg 人像抠图去背景，主要用于 LoRA 训练素材制作。
- **工作流调用配置**：可视化导入并绑定 ComfyUI API 工作流、在线试跑、保存即生成接口文档（由内置 FastAPI 子服务 comfyui-ctrl 驱动）。
- **生图工作流**：选择已注册工作流填参生图，轮询任务并查看结果与最近任务。
- **ollama测试**：应用内单轮对话测试页，同时由主进程内置的局域网 HTTP 服务对外提供同款聊天页面，局域网内其他电脑用浏览器即可访问；该服务还把工作台的显存清理能力开放为 HTTP 接口。

其中短视频下载与一键裁切头像归属于「素材工具箱」分类；工作流调用配置、生图工作流、调用文档、ollama调用说明与 ollama测试归属于「生产工具」分类。主区域采用类似浏览器的多标签页（Tab）方式承载，标签可切换、可关闭，页面状态在切换时保留。

## 2. 技术栈

| 层 | 技术 | 说明 |
| --- | --- | --- |
| 桌面框架 | Electron 13 | 主进程 + 渲染进程 + preload 预加载 |
| 前端框架 | Vue 3.2 + Vue Router 4（hash 模式） | 组合式 API 兼容的 Options API 写法 |
| UI 组件 | Element Plus 2.3 + @element-plus/icons-vue | 菜单、标签页、表格、表单、对话框等 |
| 构建工具 | Vue CLI 5（webpack 5）+ vue-cli-plugin-electron-builder | 一条命令同时跑 Web 与 Electron |
| 样式 | Sass（sass + sass-loader） | scoped 样式 |
| HTTP | axios、got@11、fetch | axios 负责文件流下载，got 负责平台接口请求，渲染层用 fetch 直连 comfyui-ctrl 子服务 |
| 代码规范 | ESLint 7（airbnb-base + vue3-recommended） | 保存可自动修复 |
| Python 子项目 | Python 3.11 + OpenCV（YuNet ONNX）+ rembg/onnxruntime | headcut：头像裁切与背景去除 |
| 内置后端服务 | FastAPI + Uvicorn + pydantic-settings + httpx | comfyui-ctrl：编排本地 ComfyUI 的工作流服务（Python 3.9+） |
| 局域网服务 | Node 原生 http + axios 流式转发 | lanserver：零新增依赖，对外提供 Ollama 聊天测试页与显存清理接口（见 8.8） |

## 4. 进程模型与 IPC 通信

应用沿用 live-download-app 的三进程结构：

1. **主进程（`src/background.js` + `src/server/`）**：拥有 Node 与 Electron 完整权限，负责窗口、文件系统、子进程、网络请求与隐藏解析窗口。
2. **预加载脚本（`src/preload.js`）**：通过 `contextBridge` 只暴露受控的 `ipcRenderer`（含 `on` / `removeListener`），渲染层默认开启 `contextIsolation`，不开启 Node 集成。
3. **渲染进程（`src/render/`）**：纯 Vue 页面，所有系统能力都通过 IPC 间接调用。

通信骨架位于 `src/server/ipc.js`，支持三种模式：

- **渲染 → 主（请求/响应）**：`ipcRenderer.invoke(event, ...args)` 配合主进程 `registHandle(event, handler)` 与 `ipcMain.handle`，是目前业务使用的主要模式。
- **渲染 → 主（异步事件）**：`ipcRenderer.on/send` 配合 `registController`，保留用于传统事件回调场景。
- **主 → 渲染（反向调用）**：主进程通过 `invokeRenderMethod({ methodName, args })` 发 PING，渲染层 `ipcMethods.js` 执行后回 PONG；当前用于 `logRender` 日志转发。头像裁切的实时进度则直接通过 `webContents.send(HEAD_CUT_PROGRESS)` 推送。

所有事件名统一定义在 `src/common/eventConst.js`，主进程与渲染层共享同一份常量，避免手写字符串出错。

## 5. 标签页导航系统

### 5.1 菜单结构

菜单与标签的配置集中在 `src/render/common/tabStore.js` 的 `menuConfig`：

- 普通菜单项：工作台（`/dashboard`，应用默认落地页，显卡状态与本地服务启停，详见第 9 节）、设置。
- 分组菜单项（`children`）在界面上渲染为可展开的 `el-sub-menu`，当前有两个：「素材工具箱」包含「短视频下载」「一键裁切头像」；「生产工具」包含「工作流调用配置」（`/prod/workflow-admin`）、「生图工作流」（`/prod/workflow`）、「调用文档」（`/prod/api-doc`）、「ollama调用说明」（`/prod/ollama-guide`）与「ollama测试」（`/prod/ollama-chat`）。

### 5.2 标签页行为

- 点击侧边栏栏目时路由跳转，`Home.vue` 监听 `$route` 调用 `openTab(path)`：标签已存在则仅激活，不存在则新建。
- 标签栏使用 `el-tabs`（card 风格），点击标签通过 `tab-click` 触发路由切换；工具标签带关闭按钮，关闭时 `closeTab` 自动跳到相邻标签。
- 工作台、设置为固定标签（`closable: false`），工具标签可关闭。
- 内容区使用 `<router-view>` 配合 `<keep-alive>` 缓存全部已访问页面，切换标签时页面数据（如下载结果、裁切表单、任务进度）不会丢失。

## 6. 短视频下载

### 6.1 页面与交互

页面：`src/render/views/BatchVideoDownload.vue`。

- **下载目录配置内嵌**：目录选择器位于功能页顶部「下载目录配置」卡片，不再放在独立设置页。选择目录后立即通过 `SET_VIDEO_WORKSPACE` 持久化；默认目录为 `文档库/SmartDesk/videoDownload`。
- 多行文本框粘贴分享链接，每行一条，支持批量。
- 任务队列组件 `components/tasklist` 串行执行下载任务并在对话框中展示进度。
- 结果表格展示作者、封面、描述、类型（视频 / 图文 / 实况照片）与打开文件 / 打开目录操作，失败原因集中在错误提示区展示。

### 6.2 主进程链路

入口：`src/server/video/downloadVideo.js`

1. `checkPL(link)` 按域名识别平台：抖音（douyin）、TikTok（tiktok）、快手（kuaishou）、小红书（xhslink / xiaohongshu）。
2. 分发到对应解析器，统一返回 `{ videoUrl, cover, user, desc, type, images, imageExts, liveVideos }` 结构。
3. 按 `视频 / 图文 / 实况照片` 分别落盘，保存路径为 `下载目录/日期/作者/时间戳.mp4`（图文为序号图片，实况照片额外保存 `_live.mp4`）。
4. 文件下载器 `src/server/download/download.js` 基于 axios 流式写入，并带无数据超时保护。

各平台解析方式：

| 平台 | 模块 | 方式 |
| --- | --- | --- |
| 抖音 | `lib/dy/dyBrowser.js` | 复用一个隐藏的 Electron `BrowserWindow`（独立 partition），加载分享链接后遍历页面 React Fiber 提取作品对象；遇到风控验证码时自动把窗口展示给用户手动完成，通过后继续解析，无需页面内嵌 webview |
| TikTok | `lib/tt/ttParser.js` | 第三方解析接口（got 请求） |
| 快手 | `lib/ks/ksParser.js` + `ksSign.js` | 跳转还原真实链接后带签名请求接口 |
| 小红书 | `lib/xhs/xhsParser.js` | 抓取笔记页 HTML，解析初始状态中的视频 / 图集数据 |

### 6.3 相对 live-download-app 的适配

- 下载目录配置从设置页迁移到功能页内部，配置后端仍复用 `config.json`，保证持久化与后续扩展。
- 移除旧版 webview 验证码弹窗、网络监听与 Cookie 清理链路（新版抖音解析器已内置隐藏窗口验证），同时移除了 `webviewTag`，降低 Electron 安全告警。
- 未迁移直播、房间管理、视频/图片裁切等无关模块及其依赖（jszip、vue-cropper 等）。

## 7. 一键裁切头像（headcut 子项目）

### 7.1 Python 子项目

子项目位于 `subprojects/headcut`，以可编辑模式安装在自带的 `.venv` 虚拟环境中，与主项目的 Node 依赖完全隔离。

- 入口：`python -m headcut <输入目录> -o <输出目录> -s 尺寸 --scale 倍数 [-r] [--remove-bg ...]`
- 人脸检测：OpenCV FaceDetector 加载包内 YuNet ONNX 模型（`headcut/models/face_detection_yunet_2023mar.onnx`，随仓库提供）。
- 裁切策略：以面积最大的主体人脸框为中心，按 `--scale` 倍数向外扩展正方形裁切框，靠近边缘自动钳制或补边，再缩放到目标边长（默认 1024）。
- 去背景（可选）：`bgremove.py` 在启用时才 import rembg，使用 `headcut/models/rembg/` 下的分割模型，支持透明底 PNG 或纯色底；模型缺失时按 ModelScope → hf-mirror → GitHub → 代理的顺序自动下载。

### 7.2 Node 侧调用

模块：`src/server/headcut/index.js`

- `resolveHeadcutHome(customHome)` 按顺序查找：界面指定目录 → 环境变量 `HEADCUT_HOME` → 开发模式 `subprojects/headcut` → 打包模式 `resources/headcut`，判定条件是目录下存在 `headcut/__main__.py`。
- `resolvePython(home)` 优先使用子项目内 `.venv` 的解释器（Windows 为 `.venv/Scripts/python.exe`）。
- 通过 `child_process.spawn` 以 `windowsHide` 启动，强制 `PYTHONUTF8=1`，逐行解析 Python 标准输出中的「共发现 N 张」「[裁切]」「[未检测到人脸]」「完成」等中文日志，实时换算百分比并经 `HEAD_CUT_PROGRESS` 事件推送到渲染层。
- 同一时刻只允许一个裁切任务，`stopHeadCut` 通过 kill 子进程停止。
- 结果管理（列表缩略图、预览、删除）在主进程完成，删除前用 `ensureInsideOutput` 校验路径必须位于输出目录内且为图片后缀，防止越权删除。

### 7.3 页面

页面：`src/render/views/HeadCut.vue`，表单参数（输入/输出目录、递归、尺寸、比例、去背景模型与底色、headcut 目录）保存在浏览器 localStorage；结果区支持缩略图网格、点击预览、单张删除与批量删除。

输出目录规则：实际裁切结果输出到「裁切结果输出目录」下、以待裁切图片目录最后一级目录名命名的子文件夹（计算属性 `resultDir`，例如输入 `E:\素材\Sxiao7`、输出配置 `E:\素材\训练素材` 时，实际写入 `E:\素材\训练素材\Sxiao7`）。裁切任务、结果列表、预览、删除、打开目录全部统一使用 `resultDir`，主进程会递归创建该目录；子目录尚未生成时结果区按空状态静默处理，不弹错误提示。

## 8. 生产工具（comfyui-ctrl 子项目）

「生产工具」分类承载基于本地 ComfyUI 的 AI 生图能力，包含两个栏目：

- **工作流调用配置**（路由 `/prod/workflow-admin`）：可视化导入 ComfyUI API 格式 JSON，自动解析节点与控件，勾选需要对外暴露的参数并完成绑定、在线试跑，保存后自动生成调用表单与 HTTP 接口文档。
- **生图工作流**（路由 `/prod/workflow`）：选择已注册工作流，按动态表单填参后提交生图，轮询任务状态并展示结果，同时保留最近任务记录，支持回填参数与再次查看结果。
- 原 comfyui_ctrl 的显存管理（GPU / VRAM / Ollama 控制）本次不迁移。

### 8.1 整体架构

原项目是 React + AntD 前端配 FastAPI 后端；迁入 SmartDesk 后保留 FastAPI 后端作为独立子项目，由 Electron 主进程托管，前端改写为 Vue 3 + Element Plus 页面：

1. **FastAPI 子服务 `subprojects/comfyui-ctrl`**：监听 `127.0.0.1:8888`，通过 httpx 编排本机 `127.0.0.1:8188` 的 ComfyUI，负责工作流解析、参数绑定校验、任务提交、结果图片回传与注册表管理，已开启 CORS 允许渲染层跨端口访问。
2. **Electron 主进程模块 `src/server/comfyui/index.js`**：应用启动时探测 8888 健康状态，未运行则用子项目 `.venv` 解释器拉起 `uvicorn app.main:app`，退出时回收；同时通过 IPC 向渲染层提供服务基址与健康状态。
3. **Vue 渲染层**：`src/render/common/comfyuiApi.js` 用 fetch 直连 8888，统一处理 `{ code, message, data }` 响应包络（`code === 0` 为成功），并把后端返回的相对图片地址拼成绝对 URL。

### 8.3 服务生命周期

`src/background.js` 在 `app.ready` 后非阻塞调用 `startComfyuiService()`，在 `window-all-closed` 与 `before-quit` 调用 `stopComfyuiService()`。

- `resolveComfyuiHome()` 依次查找：环境变量 `COMFYUI_CTRL_HOME` → 开发目录 `subprojects/comfyui-ctrl` → 打包 `resources/comfyui-ctrl`，判定条件是目录下同时存在 `app/main.py` 与 `run.py`。

- 渲染层通过 `GET_COMFYUI_BASE` 取得基址（首次获取后缓存）、`GET_COMFYUI_HEALTH` 查询就绪状态。

### 8.6.1 image 类型参数的处理链路

`LoadImage` / `LoadImageMask` 节点的 `image` 控件在 ComfyUI 中是 input 目录文件名，平台将其抽象为独立的 `image` 参数类型（解析时优先识别 `/object_info` 中的 `image_upload` 标记，元数据不可用时按节点类名兜底），避免把动态图片输入退化为固定文件名枚举：

- **入参形态**：invoke / trial 的 `params` 接受三种值——Data URL（`data:image/png;base64,...`，推荐）、不带前缀的纯 base64（按 base64 字母表与图片魔数识别，文件名因含扩展名等字符不会被误判）、input 目录已有文件名（兼容旧调用）。
- **上传与注入**：前两种值解码后由 `WorkflowService` 经 ComfyUI `POST /upload/image` 上传到 input 下独立子目录 `smartdesk/`（uuid 文件名，避免重名与目录穿越），再把 `smartdesk/<uuid>.<ext>` 注入模板的 LoadImage 控件；调用方无需感知 ComfyUI 的本地目录。
- **任务记录**：`submitted_params` 只保留解析后的文件名，不存 base64，避免任务列表携带超大字段；回填历史任务时图片参数以文件名标签展示，可重新选图覆盖。
- **临时文件清理**：任务到达终态（成功 / 失败 / 超时）后，按 `COMFYUI_INPUT_DIR` 做越权校验再删除本次上传的文件；ComfyUI 校验拒绝、任务未建立时在同一请求内即时清理；该目录未配置或路径失效时跳过清理（不影响主流程）。
- **兼容层差异**：`/v1/images/generations` 的参考图仍由 `compat_service` 直接写 `COMFYUI_INPUT_DIR`（文件名前缀 `aicompat-`），两条链路互不干扰；注意 ComfyUI Desktop 实际 input 目录可能由启动参数 `--input-directory` 指定，配置前先核对进程命令行。

接口清单：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/` | 自包含聊天测试页 HTML |
| GET | `/api/config` | 返回默认模型、Ollama 基址与是否需要鉴权 |
| GET | `/api/models` | 代理 Ollama OpenAI 兼容接口 `/v1/models`，返回模型 id 列表与默认模型 |
| POST | `/api/chat` | 入参 `{ model, message }`，代理 `/v1/chat/completions`，把上游 SSE 归一化为 `data: {"delta":"..."}\n\n` 分片，结束补发 `data: [DONE]` |
| POST | `/api/vram/release` | 复用工作台 `releaseVram()`（见 9.5），返回完整 ReleaseResult，供局域网内其他服务调用 |

### 8.9 AIComicBuilder 兼容协议（comfyui-ctrl `/v1`）

为对接 AIComicBuilder（Mac 端漫画应用）的「ComfyUI 自定义 Provider」，comfyui-ctrl 在原有 `/api/v1` 之外新增一套独立前缀的兼容路由（`app/api/routes/compat.py` + `app/services/compat_service.py` + `app/schemas/compat.py`），把对端「一次 HTTP 请求换一张图」的同步生图抽象翻译为现有工作流任务。uvicorn 由 Electron 以 `--host 0.0.0.0` 拉起，对端在同一局域网访问 `http://<本机IP>:8888/v1`，渲染层与健康探测仍走 `127.0.0.1`。

接口（响应不走 `{code,message,data}` 包络，成功为 OpenAI 风格，失败为 `{error:{type,message}}`）：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/v1/models` | 返回注册表内全部 workflow_id，供对端设置页「获取模型」 |
| GET | `/v1/loras` | 返回 ComfyUI 当前可用的 LoRA 文件名清单 `{data:[{id}]}`，`id` 可直接作为生图请求的 `lora` 参数值（实时取自 `/object_info/LoraLoader`，5 分钟缓存；ComfyUI 不可达返回 503） |
| POST | `/v1/images/generations` | 同步生图，阻塞至出图后返回 `{data:[{b64_json}]}`（固定 base64 模式，无需静态图床） |

请求体字段遵循对接文档：`model`、`prompt`（原样注入不二次改写）、`n`（恒为 1）、`size`、`aspect_ratio`、`quality`、`task_type`、`reference_images[]`（无 `data:` 前缀的 base64，含 `label/mime_type/data`）。兼容层另扩展两个可选字段：`lora`（LoRA 文件名，合法值来自 `GET /v1/loras`）与 `strength`（LoRA 强度，缺省 `1.0`）。

框架处理链路：

- **任务路由**：`task_type` 必须属于六个合法枚举，路由表 `workflows/task_routing.json` 每次请求实时读取（改完无需重启）；值为空返回 501 `workflow_not_mapped`，指向不存在的工作流返回 501 `workflow_not_registered`。路由项支持两种写法：字符串（仅 workflow_id）或对象 `{"workflow_id": "...", "param_overrides": {...}}`，`param_overrides` 在约定参数之后合并，可固定工作流参数（如 `{"lora_enabled": false}` 关闭 LoRA 插槽）。
- **宽高比翻译**：对端只给像素尺寸，兼容层把 `宽x高` 约分后翻译为工作流 `ResolutionSelector` 的枚举文案（16:9→`16:9 (Widescreen)`、9:16→`9:16 (Portrait Widescreen)`、1:1→`1:1 (Square)`）并以 `aspect_ratio` 参数注入；无法匹配的尺寸不注入该参数，由工作流默认值兜底。
- **尺寸兜底**：`size`（`宽x高`）优先，其次 `aspect_ratio` 映射（16:9→2560x1440、9:16→1440x2560、1:1→2048x2048），再缺省按 16:9。
- **参考图**：base64 解码后以 `aicompat-<uuid>.<png|jpg>` 写入 `.env` 中 `COMFYUI_INPUT_DIR` 指向的 ComfyUI input 目录（LoadImage 节点只认该目录）；未配置目录却携带参考图时返回 501；任务结束（成功或失败）后自动清理临时文件。
- **参数约定**：兼容层向工作流提交统一参数键 `prompt`、`width`、`height`、`task_type`、`ref_image`（首张文件名）、`ref_images`（文件名数组，按对端顺序，尾帧场景第 0 张即首帧）、`ref_labels`；后续对接的 definition 声明同名参数即自动注入，未声明的键被忽略。
- **LoRA 开关**：请求未传 `lora`（或空串）时强制 `lora_enabled=false`，不挂 LoRA；传入 `lora` 时置 `lora_enabled=true` 并注入 `lora_name`，`strength` 未传时按 `1.0` 注入 `lora_strength`。该逻辑在路由表 `param_overrides` 之后合并，请求显式传参优先；LoRA 文件名经工作流枚举校验，非法值返回 400 `invalid_workflow_param`。
- **排队与超时**：模块级 `asyncio.Semaphore(1)` 保证同一时刻只跑一个出图任务，并发请求在信号量上排队等待；单任务同步等待上限 `COMPAT_JOB_TIMEOUT`（默认 540 秒，对端总超时 10 分钟），超时返回 504；ComfyUI 拒绝工作流返回 502，不可达返回 503。
- **鉴权**：接收 `Authorization: Bearer` 头但不强制校验（可信内网定位，与对接文档允许的简化方案一致）。

对接进度：

- `character_turnaround` 已对接 `qwen_lora_txt2img`（千问 LoRA 文生图 turbo），默认不挂 LoRA，请求体可选传 `lora` + `strength` 开启 LoRA 插槽（不传强度按 1.0）；应用侧设置页模型 ID 填 `qwen_lora_txt2img`，请求示例见子项目 `examples/character_turnaround.request.json` 与 `examples/character_turnaround_lora.request.json`。
- `first_frame`（首帧）、`last_frame`（尾帧）、`scene_frame`（场景帧）均对接 `qwen_10_img_edit`（千问图像编辑 10 图版），三者都是多图参考调用：`reference_images` 落盘后以约定键 `ref_images`（image_list，1~10 张）注入，服务端按实际张数级联剪除多余的 LoadImage 与缩放节点；提示词经约定键 `prompt` 注入（definition 参数键与约定对齐，注入路径为工作流切换节点的 `on_false`，原样传入不二次改写）。请求示例见 `examples/first_frame.request.json`，把 `task_type` 换成另外两个值即可复用同一工作流。
- `reference`、`generic` 仍留空，后续对接只需在路由表填写 workflow_id（无需改代码）。

## 9. 工作台（显卡状态与服务启停）

工作台是应用的默认落地页（路由 `/dashboard`，固定标签不可关闭），页面为 `src/render/views/Dashboard.vue`，主进程逻辑集中在 `src/server/dashboard/index.js`。功能分四块：显卡挂载识别、显存总占用仪表盘、三个常用软件的启停管理、一键显存清理。comfyui_ctrl 的显存管理基于 Python NVML（pynvml）并展示进程级明细，工作台只借鉴其「健康探测 + 进程控制 + 显存释放」思路，显卡查询改用驱动自带的 `nvidia-smi`，在 Electron 主进程内完成，不引入额外 Python 依赖，也不展示进程级占用明细。

### 9.1 显卡挂载识别

- 本机为外置显卡（eGPU）方案，显卡未上电或连接异常时 `nvidia-smi` 命令直接失败。主进程依次尝试 `%SystemRoot%\System32\nvidia-smi.exe` 与 PATH 中的 `nvidia-smi`，命令报错或无输出即判定为未挂载，返回 `available: false` 与中文错误原因。
- 轮询并发去重：探测进行中再次请求时复用上一次结果（`gpuProbeInFlight` + `lastGpu`），避免短轮询堆积子进程。
- 渲染层在未挂载时展示高红色 `el-alert`（红色描边 + 加粗「显卡未挂载」标题），并提示检查供电、雷电 / OCuLink 连接与驱动；显卡恢复挂载后下一次轮询自动恢复正常展示，无需重启应用。

### 9.2 显存占用仪表盘

- 已挂载时通过 `--query-gpu=name,memory.total,memory.used,memory.free --format=csv,noheader,nounits` 一次查询全部显卡，多卡时聚合成 `totals`（总 / 已用 / 剩余 MiB 与占用百分比）。
- 页面只展示一个 `el-progress`（dashboard 仪表盘）+ 绝对值（GB）与百分比，不展示进程级明细；仪表盘颜色按占用率 70% / 90% 切换绿 / 橙 / 红。

### 9.3 受管服务与启动发现

| 服务 | 端口 | 健康探测 | 浏览器入口 | 默认启动程序发现 |
| --- | --- | --- | --- | --- |
| Ollama | 11434 | GET `/api/version` | 无 | `%LOCALAPPDATA%\Programs\Ollama\ollama.exe serve`，找不到时回退 PATH 中的 `ollama` |
| ComfyUI | 8188 | GET `/system_stats` | http://127.0.0.1:8188 | 扫描 `COMFYUI_HOME`（默认 `D:\Comfy-Desktop\ComfyUI-Installs`）下各实例，优先 `ComfyUI\.venv\Scripts\python.exe`，旧版 Desktop 布局回退 `standalone-env\python.exe`，以 `-s ComfyUI/main.py --listen 127.0.0.1 --port 8188 --enable-manager` 启动，并自动挂载共享模型 / 输入 / 输出目录（见下） |
| AcademiaSD | 4990 | GET `/` | http://127.0.0.1:4990 | `ACADEMIA_HOME`（默认 `E:\aiwork\AcademiaSD_LoRAlab-TrainerStudio`）下 `venv\Scripts\python.exe scripts\launcher.py` |

- 健康探测为 2.5 秒超时的 HTTP GET，拿到任意非 5xx 响应即视为在线，连接拒绝安全降级为离线，不抛异常。
- 启动：`spawn` 拉起 detached 子进程，标准输出 / 错误追加到 `userData/SmartDesk/logs/dashboard-<id>.log`。先在 30 秒快速窗口内轮询健康探测，窗口内就绪返回成功、进程提前退出返回退出码与日志路径；窗口结束进程仍存活则返回 `starting` 状态（不判失败），由工作台 5 秒轮询自动接管，端口就绪后开关自动翻为「运行中」。已在启动中的服务重复点击启动不会二次拉起，直接复用现存进程。
- 停止：除按端口 / 进程树结束外，对「启动中」（端口尚未监听）的服务也会结束本模块拉起的子进程，并同时确认进程退出与端口离线两个条件。
- ComfyUI 冷启动耗时说明：`ComfyUI_Custom_Nodes_AlekPet` 等自定义节点会在导入时对缺失依赖执行 `pip install`，其中 ArgosTranslateNode 的 git 依赖（github.com）在国内网络下克隆失败会拖慢启动，实测完整冷启动约 2~3 分钟；该失败在 Desktop 正常启动中同样存在且不致命，节点标记失败后服务仍会就绪。等待期间工作台显示「启动中」属预期现象，可在日志中查看进度。
- ComfyUI 共享目录挂载：直接运行 `main.py` 时 ComfyUI 只扫描安装目录内的 `models`、`input`、`output`，不会使用 `D:\Comfy-Desktop\ComfyUI-Shared`。启动命令会按以下顺序补齐配置：
  - 模型目录：读取 `%APPDATA%\Comfy Desktop\installations.json`，按安装路径匹配实例 id，复用 Desktop 生成的 `instance-model-paths\inst-<id>.yaml`，通过 `--extra-model-paths-config` 传入；匹配失败时回退到该目录下任意 yaml，仍找不到则在 `userData/SmartDesk/comfyui-extra-model-paths.yaml` 生成等价配置（指向 `COMFYUI_SHARED_HOME`，默认 `D:\Comfy-Desktop\ComfyUI-Shared\models`，仅在共享目录存在时生成且不重复写）。
  - 输入 / 输出目录：读取 Desktop `settings.json` 的 `inputDir` / `outputDir`（缺省回退 `ComfyUI-Shared\input`、`ComfyUI-Shared\output`），目录存在时分别通过 `--input-directory`、`--output-directory` 传入。
  - 同时带 `--enable-manager`，与 Desktop 的 `launchArgs` 行为对齐。以上路径均可在 `dashboard-services.json` 覆盖启动参数时自行调整。
- 停止：Ollama 按映像名 `taskkill /F /T /IM ollama.exe`、`ollama app.exe` 整树结束（避免托盘程序自动重启 serve）；ComfyUI / AcademiaSD 先结束本模块拉起的进程树，再通过 `netstat -ano -p tcp` 定位监听端口的 PID 整树结束，最长等待 15 秒确认离线。
- 同一服务的启停操作通过 `pending` 映射串行化，并发点击直接复用进行中的任务。
- 启动命令覆盖：默认位置找不到程序时，可在 `userData/SmartDesk/dashboard-services.json` 配置，格式为 `{ "services": { "comfyui": { "command": "...", "args": [...], "cwd": "..." } } }`，覆盖项与自动发现结果合并；页面会提示该配置文件的绝对路径。
- 浏览器入口通过 `shell.openExternal` 调用系统默认浏览器，仅 ComfyUI 与 AcademiaSD 提供，服务离线时按钮禁用。

### 9.4 前端交互

- 进入页面立即拉取一次总览（`GET_DASHBOARD_OVERVIEW` 一次返回显卡数据与三个服务状态），默认每 5 秒轮询；`<keep-alive>` 下通过 `activated` / `deactivated` 自动启停定时器，切到其他标签时不产生无效探测。
- 服务开关为受控 `el-switch`，状态以后端总览为准；操作期间按钮 loading，成功 / 失败均有消息提示，结束后立即刷新一次总览。
- 顶部提供「自动刷新」开关与「立即刷新」按钮，并展示最近刷新时间。

### 9.5 显存清理

显存清理对齐 comfyui_ctrl 的 `vram_service`，只回收模型驻留显存，不停止服务进程；AcademiaSD 的训练进程不参与清理。

- **Ollama**：先 `GET /api/ps` 枚举驻留模型，无模型直接返回；否则对每个模型 `POST /api/generate` 并带 `keep_alive: 0` 通知立即卸载，`ollama serve` 进程保持运行。
- **ComfyUI**：`POST /free`，请求体 `{ "unload_models": true, "free_memory": true }`，触发模型卸载与 CUDA 缓存回收。
- 服务不可达（连接拒绝、无 HTTP 响应）时该步骤标记为「跳过」而不是失败；两个服务都不可达时整体提示未执行回收。
- 两个 API 返回后驱动层面的显存回收是异步的，主进程等待 6 秒（`VRAM_SETTLE_MS`）再用 `nvidia-smi` 统计清理前后的占用差值，返回每步结果与释放 MiB；清理期间通过 `vramPending` 去重，重复点击复用同一次任务。
- 显卡未挂载时直接返回失败提示，不调用任何服务接口。
- 同一清理逻辑经局域网服务开放为 `POST /api/vram/release`（见 8.8），局域网内其他服务可直接 HTTP 调用，curl 示例集中在「ollama调用说明」页。
- 前端入口为显卡卡片右上角的「清理显存」按钮（显卡未挂载时禁用），清理中按钮 loading，完成后在卡片内展示各服务的成功 / 跳过 / 失败标签与消息，并自动刷新仪表盘数据。

## 13. 打包发布

`vue.config.js` 的 electron-builder 配置中声明了 `extraResources`，打包时会把 `subprojects/headcut`（排除 `__pycache__`、`.pyc`、日志）复制到安装包的 `resources/headcut`，主进程 `resolveHeadcutHome` 已包含该候选路径。

打包注意事项：

- 目标机器若不带 `.venv`，需要在打包镜像内预置虚拟环境，或改造为安装后首次运行自动创建 venv 并 pip 安装（当前默认把 `.venv` 一并打包，因 `.gitignore` 只影响 Git 不影响 extraResources）。
- Windows 目标为 NSIS 安装包（`win.target = nsis`）。
- 分割大模型不进 Git，发布前需确认 `resources/headcut/headcut/models/rembg/` 内模型齐全，或依赖首次运行自动下载。
- `subprojects/comfyui-ctrl` 同样通过 `extraResources` 复制到 `resources/comfyui-ctrl`（排除 `__pycache__`、`.pyc`、日志、`workflows/outputs`、`workflows/backups`、`doc`），主进程 `resolveComfyuiHome` 已包含该候选路径；目标机器需自带可用的 `.venv`，或后续改造为首次运行自动建环境。

## 14. 已知限制与后续扩展

- 平台解析依赖第三方页面结构与接口，抖音 / 快手等改版后可能需要更新对应 parser。
- TikTok 解析走第三方接口，无作者与简介信息（界面会显示占位文案）。
- headcut 同一时刻仅支持一个裁切任务；多任务排队可作为后续增强。
- 标签页目前缓存全部已打开页面，后续功能增多时可在 `tabStore` 中加入最大缓存数与销毁策略。
- 设置页为占位页，后续应用级配置（如下载并发数、通知、代理）可在此扩展。
- comfyui-ctrl 依赖本机 8188 端口的 ComfyUI 在线，ComfyUI 不可达时生图 / 试跑返回 503；任务记录仅存内存，重启子服务后最近任务清空。
- 工作流导入仅接受 ComfyUI API 格式 JSON，UI 图格式（nodes/links 数组）会被拒绝。
- 工作台的显卡探测与进程管理依赖 Windows 的 `nvidia-smi`、`netstat`、`taskkill`，目前仅支持 Windows + NVIDIA 方案，不含 AMD / 核显与跨平台适配。
- 服务启停依赖默认安装路径自动发现，非默认安装需通过 `dashboard-services.json` 覆盖启动命令；停止逻辑按监听端口定位进程，若端口被其他程序占用会被误判为对应服务在线。
- 工作台只负责拉起 / 结束进程，不托管服务自身配置（如 ComfyUI 的模型目录、Ollama 的模型存储）；外置显卡未挂载时 ComfyUI 等 GPU 服务即使进程存活也无法正常推理。
- 显存清理仅覆盖 Ollama 与 ComfyUI 的模型驻留显存，不处理 AcademiaSD 训练进程或其他程序占用的显存；清理前后的差值包含 6 秒等待期内其他进程的自然波动，可能出现小幅负值。
- 局域网 HTTP 服务为明文 HTTP、仅提供单令牌 Bearer 鉴权，设计上只面向可信局域网；如需公网访问应自行在前置网关增加 HTTPS 与访问控制。聊天接口为单轮对话，不携带多轮上下文。
